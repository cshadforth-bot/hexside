Design & Playtest Report

Hexside — Character Skins

Twelve optional alternate Player Roster cards, designed, wired into both engines, and verified — from first sketch to 4,000 clean matches across both engines
2026-09-17, updated 2026-09-21 hexside-character-cards.html · engine/sim.py · both playtest drivers All batches: real dice, real random draft, randomized rosters

1 Twelve characters, one design rule Cards built

The standard five positions play the same on both sides of the ball — the idea this session added was optional personality: amateur five-a-side archetypes (the unfit one, the enforcer, the one who takes it far too seriously) a side can swap in for any of its five slots before kickoff, one alternate per slot at most. Twelve were built: one for Goalkeeper, two or three each for the other four.

Every one of the five standard positions already carries a Signature ability — Shot-Stopper, Overlap, Last Man, Vision, Clinical — a small once-per-match or once-per-turn power. Rather than invent new always-on mechanics per character, each skin is a small stat delta from its base slot (kept inside the range the standard five already span) plus a themed replacement Signature reusing that same slot. It's a hand-tuned power budget the game already ships with five real examples of — reusing it, instead of asking for twelve bespoke new systems, is what made the rest of this session's work tractable.

2 The K3 occupancy crash Root-caused & fixed

ValueError: OCCUPANCY CONFLICT: K3 holds both A-PO and A-SW — surfaced incidentally during an unrelated house-rule trial, then root-caused on request rather than left tolerated. Two bugs stacked: an Emergency Goalkeeper deputy wasn't reserved into its zone before the normal restart draft, the way the real Goalkeeper always is — so another unit could legally draft onto the exact zone hex the deputy needed a moment later. When that happened, _zone_hex()'s own fallback silently handed back the first zone hex anyway — a hex it had just proven was occupied.

Fixed at both points: formation() now reserves a deputy's zone hex in the same upfront step the real Goalkeeper already uses (and the deputy stays eligible as a last-resort kickoff taker, unchanged); _zone_hex() now widens its search — the zone's own neighbors, then the whole board — instead of ever handing back a hex it just proved was taken.

  • 40,000+ direct formation() trials with a forced Emergency Goalkeeper (including both sides deputized at once, and the deputy-as-only-unit-left edge case) — zero crashes, zero overlaps
  • Both drivers re-run clean at N=1000 afterward, one run hitting 1,357 sin-bin trips (heavy Emergency-Goalkeeper exercise) with zero conflicts

3 Signature abilities, both drivers Implemented

All twelve Signatures went from card text to real engine behavior this session, in driver_base.py (Base Game) first, then driver.py (Advanced). The five standard Signatures were already hardcoded by slot code (if unit == 'PO': # Clinical); rather than bolt twelve special cases on top, every roster slot now carries a sig key, and every trigger point dispatches on that key instead — a swapped-in character roster drives the exact same code a standard one does, confirmed by a direct regression check (standard five, no characters, all pre-existing Signature rates unchanged).

Porting from Base to Advanced wasn't a copy-paste in two places, both found by reading the target driver's actual code rather than assuming it matched:

  • Sees Red reuses Strong Tackle's own dice logic. Base's first version borrowed the real sim.strong_tackle() function by temporarily slipping a fake card into an always-empty hand. Advanced's hand is not always empty — a genuine Strong Tackle card can be sitting there at the same moment, and the same trick would risk leaving a duplicate behind. Reimplemented to call the dice/discipline logic directly, never touching the card economy at all.
  • Showman has zero code in Base — its trigger (playing Nutmeg or Step-Over) is a Tactic-deck card Base never deals, so there was nothing to hook. Real implementation landed only in Advanced, inline inside dribble_contest().

Main Character (Me!) was implemented, then deleted: tracing every place the engine's own "Through on Goal" flag gets set showed it can only ever become true inside a code branch that's mutually exclusive with the one a Pass-instead-of-Shot decision would need — this driver never actually offers that choice to any character, so there was nothing left to override. Confirmed independently in each driver (and, later, in the digital board too) rather than assumed to carry over from one to the other. A one-off KeyError: 'GK' was also caught and fixed in testing: Playing Out is the first way a Goalkeeper can ever reach a real Shot attempt, a code path the shot-tracking stats had never needed a slot for before.

2026-09-21 redesign: once real batch data confirmed Me! was structurally inert (see §5), "Main Character" was replaced outright rather than left as a permanently dead card. New effect: once/match, reroll all Blank dice on a Shot, not just one — the same mechanism as Clinical, sized up, in all three implementations (both drivers and the digital board). "He never misses the big moment" keeps the flavor; the card name and slot are unchanged.
  • N=400 on each driver after the full port, plus a 60-game smoke test before every scale-up — zero crashes throughout
  • All 11 implementable Signatures fired substantially in every batch (dozens to hundreds of times each per 400 games) — genuinely reachable, not just wired
  • Real Strong Tackle plays and Sees Red confirmed firing side-by-side in Advanced with no interference between them

4 Playing Out — three rounds of correction Corrected live

"Playing Out" lets a Goalkeeper leave its own zone for one activation. What happens next went through three real design passes in one sitting, each one a genuine behavior change, not a polish pass — worth recording as a process, not just a final answer.

  • First build The Goalkeeper snapped back into its zone instantly, same turn, no matter what. Safe, but asked directly "how does it get back?" showed the honest answer was nothing does it — there was no return code at all. Direct testing confirmed a stranded Goalkeeper has zero legal moves home on its own: the zone-lock filter only checks hexes reachable from where it already stands, with no fallback once that stops including the zone at all — the ordinary result of chasing the ball toward the opponent's goal, not a rare edge case. Left as-is, that's a free, unsaved goal on the very next shot faced.
  • First correction "The goalkeeper is forced to return... the next turn" — the instant teleport was too safe. A real one-turn exposure window, where the zone genuinely sits open, is the point of a card whose own flavor says it "occasionally undoes the whole team." Reworked to a pending-return flag, resolved at the start of the side's own next turn.
  • Second correction Even a forced return next turn shouldn't be guaranteed — "if his route is blocked... and his pace can't get him back... he gets a yellow card," chosen explicitly over a version where the return still always succeeds. Reworked again: a genuine Pace-limited legal_reach() attempt, blockable like any real move. Empty (the common outcome once it's wandered far) means a guaranteed Yellow Card, applied directly rather than a random Discipline Deck draw — which then does everything else for free through code that already existed: permanent Pace −1, a one-turn sin-bin trip with the zone genuinely open the whole time, and an automatic return to zone the moment it comes back, via the sin-bin's own pre-existing logic. A second failure escalates to a Red Card the same organic way, sending the real Goalkeeper off entirely.
Stress-testing the second correction (forcing this character onto both sides to maximize how often the check fires) hit a genuine KeyError: 'GK'. Root cause: nothing in the Discipline system had ever checked whether a unit being carded and pulled off the pitch was the current ball carrier — unreachable before, since every existing card-triggering event (a lost Tackle, a Foul) always lands on whoever initiated the challenge, never the passive carrier. Playing Out's own forced-return check is the first code path that can card the carrier directly. Fixed once, at the engine level (a new _drop_ball_if_holding() helper in apply_discipline/send_to_sinbin), rather than patched only where it happened to surface — it protects every future caller with the same shape, in both drivers at once.
  • 300-game batches forcing this character onto both sides, in both drivers, after every correction — zero crashes on the final version
  • Direct before/after tests on the return mechanism itself, not just full-match runs: confirmed empty in the stranded case, confirmed correct in the successful-return case
  • Final failure-to-return rate: ~0.4–0.5% of uses across n=1000 in each driver — real, rare, not dead

5 Final verification — n=2000, both drivers

An initial n=1000-per-driver pass came back clean; a follow-up doubled it to 2000 matches per driver (4000 total), a fresh random character in every slot every match on top of the engine's own already-randomized formation draft and kickoff draft — the most exercise any single verification pass has given this system.

Goals per match ranged 0–11 across both drivers, with the same long thin tail of high-scoring outliers. Since Me!'s redesign (§3), his pick shows up disproportionately among the highest-scoring and most lopsided matches in both drivers — expected, not a balance concern: "reroll all Blanks" is a direct conversion boost, so more of his Shots landing naturally means more goals when he's fielded, without his overall pick rate shifting (still an even ~1-in-3 of the PO slot in both drivers). Advanced's higher cards/match is expected too, not a regression: Strong Tackle, Foul, and Press all add discipline-drawing chances Base's permanently empty Tactic hand never gets.

Both rosters' pick distributions came back even across the full 2000-game samples (no character starved of exercise), and batch_stats.json was confirmed to hold the user's own real prior data intact after every run — the harness that reuses each driver's run_match() has to import the file itself, which runs a small throwaway match as a side effect unless guarded.

One counting quirk turned up at this scale, in the test harness only: a handful of matches (0/2000 Base, 24/2000 Advanced in this pass; 2/2000 and 15/2000 in the prior one — the rate itself varies batch to batch, as expected for a low-probability timing quirk) log a slightly different red-card count depending on which of two counters is asked — sent_off (a direct list, authoritative) versus reds (detected by scanning a fixed trailing slice of that match's event log, which can occasionally double-count or miss one when two cards land close together). Root-caused to the log-scanning method itself, not the Discipline rules — apply_discipline was confirmed to record exactly one send-off per card, every time. Harness-only; the shipped rules and both drivers' actual card enforcement are unaffected.
